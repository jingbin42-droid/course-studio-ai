# Course Studio AI 路线图

## 1. 最终定位与路线原则

Course Studio AI 是“AI 课程团队工作与经营中枢”，采用“一个课程项目、两个业务闭环、一个 AI 全能合伙人”。

- P0 先闭合团队工作：规划、执行、记录、日报和次日计划。
- P1 再闭合课程经营：素材与知识、经营数据、分析和改进任务。
- P2 才考虑外部集成、自动发布、Cron、定时自动化、pgvector 和更高级 AI 自动化。
- 所有阶段坚持真实数据、人工确认、RLS、不做 CRM、不保存客户个人隐私、不建设复杂财务系统。
- 每个阶段完成后等待验收，不提前进入下一阶段。

## 2. 阶段 0：产品规划（已完成）

### 目标

形成团队对产品边界、业务流程、数据模型和 AI 原则的共同理解。

### 交付物

- `AGENTS.md`
- `README.md`
- `docs/PRD.md`
- `docs/ARCHITECTURE.md`
- `docs/DATABASE.md`
- `docs/WORKFLOW.md`
- `docs/AI_DESIGN.md`
- `docs/ROADMAP.md`

### 完成条件

- 产品明确不是 CRM。
- 今日工作台、课程全流程、自然语言记录、日报、明日规划、AI 合伙人、知识库、交接和依赖均有清晰定义。
- PRD、架构、数据库和工作流术语一致。
- P0 与后置能力边界明确。
- 产品负责人审阅并明确同意进入下一阶段。

### 本阶段不做

- 网站代码和工程初始化；
- 依赖安装；
- Supabase 项目或表创建；
- OpenAI API 接入；
- UI 视觉实现。

## 3. 阶段 1：基础设施与身份权限（当前批准阶段）

### 范围

- 初始化 Git、Next.js、TypeScript、Tailwind CSS 和 shadcn/ui 基础。
- 配置 Supabase 浏览器端与可信服务端访问。
- 建立登录、退出和基础受保护页面。
- 建立 `workspaces`、`profiles`、`workspace_members` 及 owner/member 权限。
- 支持创建工作空间和三名成员进入同一工作空间。
- 建立 migrations、RLS、环境变量示例、错误处理和测试框架。

### 完成条件

- 本地可运行并看到登录页。
- 配置 Supabase 后可登录和退出。
- 三名成员能进入同一个 workspace。
- 不同 workspace 数据通过 RLS 隔离。
- Secret Key 和 OpenAI API Key 不进入浏览器或 Git。
- 类型检查、测试和生产构建通过。

### 明确不做

课程项目、任务、交接业务、工作记录、日报、AI、pgvector、Cron 和自动化工作流。

## 4. 阶段 2：P0 课程与人工协作

### 目标

建立课程、任务、依赖、阻塞、交接和今日工作台的人工协作闭环。

### 范围

- 创建课程、里程碑、工作项、依赖和项目事件。
- 实现交接当前状态与 `handoff_events` 完整历史。
- 实现今日工作台的真实任务、等待关系和上线/销售缺口。

### 完成条件

- 可完成“创建课程 → 分配任务 → 建立依赖 → 退回修改 → 重新提交 → 验收”。
- 首页正确显示今日任务、阻塞和待处理交接。
- 无真实数据时只显示空状态，不显示虚构完成率。

## 5. 阶段 3：P0 记录、日报、计划与 AI 合伙人

### 目标

打通第一条完整 AI 闭环：记录事实 → AI 整理 → 人确认 → 日报与次日行动。

### 范围

- 自然语言工作记录和原文保存。
- OpenAI 服务端调用、结构化输出和调用审计。
- 工作记录解析与动作预览。
- 个人日报和团队日报草稿、编辑、确认。
- 规则候选 + AI 整理的明日计划。
- AI 失败时的手动降级体验。
- AI 项目问答、来源引用和轻量宣传草稿。

### 完成条件

- AI 不可用时仍能正常保存记录和管理工作。
- 任务或交接变化必须经过用户确认。
- 日报关键陈述有来源，冲突和缺失信息被标出。
- 次日确认计划可以进入今日工作台。
- 用固定样例完成 AI 质量评估。

## 6. 阶段 4：P1 素材、知识与决策记忆

### 目标

沉淀课程素材、团队知识和已确认决策。

### 范围

- 课程素材索引、版本和外部链接。
- 知识条目的创建、确认、标签和课程关联。
- 使用 `knowledge_entries.decision` 保存决策记忆。
- 使用全文关键词和元数据检索。
- 回答引用、权限过滤和提示注入测试。

### 完成条件

- AI 能引用已确认知识和决策并区分草稿。
- 决策包含原因、参与成员、影响范围、关联任务和后续跟进。
- 不引入 pgvector、分块或 embedding 流程。

## 7. 阶段 5：P1 课程经营与 AI 分析

### 目标

用真实聚合数据闭合课程经营循环。

### 范围

- 按课程、渠道和业务日期记录曝光、点击、咨询、订单和销售额。
- 宣传效果复盘、渠道比较和简单转化指标。
- AI 经营分析、优化建议和确认后创建改进任务。

### 完成条件

- 只保存聚合数据，不保存客户个人信息或单笔订单。
- 未知指标保持为空，AI 不补齐或编造。
- AI 区分数字事实、相关性推断和建议。
- 改进任务经用户确认后进入团队工作闭环。

## 8. P2 候选能力

只有试用证据充分时再评估：

- 素材文件上传和版本管理；
- 日历与固定日报提醒；
- 内容平台发布集成；
- 运营指标导入和跨课程趋势；
- 更细的通知偏好；
- 课程模板复制；
- 团队扩大后的权限与更多角色。
- Cron、定时日报、自动通知和自动化工作流；
- pgvector、向量检索、重排和高级知识检索；
- 更高级的 AI 自动化和多 Agent 能力。

这些能力全部属于 P2，不应进入 P0/P1，也不能阻塞基础闭环上线。

## 9. 推荐的首个试点

选择一门正在策划或刚进入制作阶段、计划周期 2–4 周的真实课程。它应同时需要 A、B、C 协作，并包含至少一次素材交接和一次上线发布。

避免用已经结束的课程作为唯一试点，因为回放数据无法验证团队是否愿意在工作中实时记录、接收交接和确认计划。

## 10. 当前决策点

当前只执行阶段 1：基础设施与身份权限。完成后必须等待产品负责人验收，不提前实现课程、任务、AI、经营数据、pgvector、Cron 或自动化工作流。
